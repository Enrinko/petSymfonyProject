# 3. Формирование страниц

Страница в этом проекте состоит из трёх уровней:

1. **Контроллер** — обрабатывает запрос и передаёт данные в шаблон
2. **Twig-шаблон** — HTML-структура страницы
3. **React-компонент** — интерактивная часть интерфейса (опционально)

---

## Уровень 1 — Контроллер

Контроллер принимает запрос и рендерит шаблон. Данные передаются вторым аргументом `render()`.

```php
// src/Controller/HomeController.php

#[Route('/')]
public function home(): Response
{
    return $this->render('base.html.twig');
}
```

Передача данных в шаблон:

```php
#[Route('/products')]
public function productList(): Response
{
    return $this->render('product/list.html.twig', [
        'title'    => 'Список товаров',
        'products' => ['Apple', 'Banana'],
    ]);
}
```

## Уровень 2 — Twig-шаблон

### Базовый шаблон и layout'ы

`templates/base.html.twig` — минимальный HTML-каркас (head, favicon, `encore_entry_*_tags('app')`). Страницы наследуются не от него напрямую, а от одного из двух layout'ов:

| Layout | Для чего |
|---|---|
| `templates/layout/shell.html.twig` | Рабочие экраны: сайдбар, топбар, блок `content` |
| `templates/layout/auth.html.twig` | Экраны входа/регистрации: сплит с бренд-панелью, блок `auth_content` |

Ключевые элементы base.html.twig:

| Элемент | Назначение |
|---------|-----------|
| `{% block title %}` | Заголовок вкладки браузера |
| `{{ encore_entry_link_tags('app') }}` | Скомпилированный CSS из Webpack |
| `{{ encore_entry_script_tags('app') }}` | Скомпилированный JS из Webpack |

### Создание новой страницы приложения

```twig
{# templates/about/index.html.twig #}
{% extends 'layout/shell.html.twig' %}

{% block title %}О проекте — petSymphony CRM{% endblock %}
{% block page_title %}О проекте{% endblock %}

{% block content %}
    <div class="card">
        <div class="card__body">{{ description }}</div>
    </div>
{% endblock %}
```

## Уровень 3 — React-компонент

### Как подключить компонент к шаблону

В Twig-шаблоне:

```twig
<div {{ react_component('ForgotPasswordForm') }}></div>
```

Symfony UX React автоматически находит компонент по имени в папке `assets/react/controllers/`.

Передача пропсов из Twig в React (реальный пример со страницы входа):

```twig
<div {{ react_component('LoginForm', {
    csrfToken: csrf_token('authenticate'),
    loginUrl: path('api_login'),
    redirectUrl: path('app_home')
}) }}></div>
```

### Эталонный React-компонент (assets/react/controllers/ForgotPasswordForm.tsx)

Самая простая «живая» форма проекта — по её образцу пишутся новые:

```tsx
import { FormEvent, useState } from 'react';
import { PasswordResetApiService } from '../services/PasswordResetApiService';
import { ApiError } from '../services/httpClient';
import Alert from '../components/ui/Alert';
import Button from '../components/ui/Button';
import TextField from '../components/ui/TextField';

type Status = 'idle' | 'loading' | 'sent' | 'error';

export default function ForgotPasswordForm() {
    const [email, setEmail] = useState('');
    const [status, setStatus] = useState<Status>('idle');
    const [error, setError] = useState<string | null>(null);
    const apiService = new PasswordResetApiService();

    const handleSubmit = async (e: FormEvent) => {
        e.preventDefault();
        setStatus('loading');

        try {
            await apiService.requestReset(email);
            setStatus('sent');
        } catch (err) {
            setError(err instanceof ApiError ? err.message : 'Не удалось отправить письмо.');
            setStatus('error');
        }
    };

    // …рендер формы на компонентах ui/TextField, ui/Button, ui/Alert
}
```

Обратите внимание на паттерн: сервис бросает типизированный `ApiError`, компонент показывает `err.message` — разбор HTTP-статусов и конверта ошибок происходит в одном месте (`httpClient`), а не в каждом компоненте.

### Создание нового React-компонента (пошагово)

#### Шаг 1 — Создать файл компонента

```tsx
// assets/react/controllers/UserProfile.tsx
import { useState } from 'react';

interface Props {
    userId: number;
    userName?: string;
}

export default function UserProfile({ userId, userName = 'Гость' }: Props) {
    const [isEditing, setIsEditing] = useState(false);

    return (
        <div className="card">
            <div className="card-body">
                <h5>Пользователь #{userId}</h5>
                <p>{userName}</p>
                <button
                    className="btn btn-primary"
                    onClick={() => setIsEditing(!isEditing)}
                >
                    {isEditing ? 'Сохранить' : 'Редактировать'}
                </button>
            </div>
        </div>
    );
}
```

> **Важно:** файл должен лежать в `assets/react/controllers/` и экспортировать компонент через `export default`.

#### Шаг 2 — Подключить в Twig-шаблоне

```twig
<div {{ react_component('UserProfile', { 'userId': 42, 'userName': 'Иван' }) }}></div>
```

#### Шаг 3 — Пересобрать ресурсы

```bash
# Разовая сборка
npm run dev

# Или следить за изменениями
npm run watch
```

После этого компонент появится на странице.

## Как работает регистрация React-компонентов

Файл `assets/app.ts`:

```typescript
import { registerReactControllerComponents } from '@symfony/ux-react';
registerReactControllerComponents(require.context('./react/controllers', true, /\.([jt])sx?$/));
```

Webpack автоматически находит все `.tsx`, `.ts`, `.jsx`, `.js` файлы в `assets/react/controllers/` и регистрирует их как компоненты. Имя компонента в `react_component()` совпадает с именем файла (без расширения).

| Файл | Имя в react_component() |
|------|------------------------|
| `assets/react/controllers/LoginForm.tsx` | `'LoginForm'` |
| `assets/react/controllers/UserProfile.tsx` | `'UserProfile'` |
| `assets/react/controllers/admin/UserRoleManager.tsx` | `'admin/UserRoleManager'` |

## HTTP-запросы из React в Symfony

Все запросы идут через единый клиент `assets/react/services/httpClient.ts`. Он в одном месте решает сквозные вопросы: JSON-заголовки, `X-Requested-With`, таймаут, разбор конверта ошибок `{message, errors}` в типизированный `ApiError`, редирект на `/login?expired=1` при 401.

Поверх клиента — доменные сервисы (`AuthApiService`, `PasswordResetApiService`, `RbacApiService`): по одному методу на эндпоинт, с типизированными ответами. **Новые вызовы API добавляются в доменный сервис, а не `fetch` в компоненте.**

```typescript
// assets/react/services/ProductApiService.ts — пример нового сервиса
import { httpClient } from './httpClient';

export interface Product {
    id: number;
    name: string;
}

export class ProductApiService {
    getProducts(): Promise<Product[]> {
        return httpClient.get<Product[]>('/api/products');
    }

    createProduct(name: string): Promise<Product> {
        return httpClient.post<Product>('/api/products', { name });
    }
}
```

Обработка ошибок в компоненте:

```tsx
try {
    const products = await apiService.getProducts();
} catch (err) {
    if (err instanceof ApiError) {
        // err.status — HTTP-код, err.message — текст из конверта,
        // err.errors — карта ошибок валидации по полям (или null)
    }
}
```

## Полный пример: новая страница с React-компонентом

### 1. Контроллер

```php
// src/Controller/HomeController.php
#[Route('/users')]
public function users(): Response
{
    return $this->render('users.html.twig', [
        'pageTitle' => 'Пользователи',
    ]);
}
```

### 2. Шаблон (templates/users.html.twig)

```twig
{% extends 'base.html.twig' %}

{% block title %}{{ pageTitle }}{% endblock %}

{% block body %}
    <div class="container mt-4">
        <h1>{{ pageTitle }}</h1>
        <div {{ react_component('UserList') }}></div>
    </div>
{% endblock %}
```

### 3. Компонент (assets/react/controllers/UserList.tsx)

```tsx
import { useState, useEffect } from 'react';

export default function UserList() {
    const [users, setUsers] = useState<string[]>([]);

    useEffect(() => {
        fetch('/api/users')
            .then(r => r.json())
            .then(data => setUsers(data));
    }, []);

    return (
        <ul>
            {users.map((user, i) => <li key={i}>{user}</li>)}
        </ul>
    );
}
```

### 4. Сборка

```bash
npm run dev
```

### 5. Открыть страницу

```
https://localhost/users
```

## Глобальные стили

Файл `assets/styles/app.css` подключается через `app.ts` и применяется ко всем страницам.
Дополнительные стили конкретной страницы можно добавить прямо в шаблон:

```twig
{% block stylesheets %}
    {{ parent() }}
    <style>
        .my-custom-class { color: red; }
    </style>
{% endblock %}
```
