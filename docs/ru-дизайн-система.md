# Дизайн-система «Ink & Brass»

Тёмный чернильный + тёплая «нотная бумага» + латунный акцент. Живая витрина всех примитивов — **`/styleguide`** (ROLE_ADMIN), она работает в обеих темах и служит регресс-инструментом после правок SCSS.

## Главное правило

**Цвета в partial'ах — только через CSS-переменные из `_tokens.scss`.** Хардкод протекает в тёмной теме «Ноктюрн». Для полупрозрачностей — RGB-каналы:

```scss
background: rgba(var(--brass-rgb), 0.16);   // да
background: rgba(200, 144, 44, 0.16);       // нет
```

Единственное осознанное исключение — `#fff` внутри `@media print` (печатные листы вне тем).

## Темы

- Светлая — базовый набор `:root`; тёмная «Ноктюрн» — переопределения в `:root[data-theme='dark']`.
- Атрибут темы ставит инлайн-скрипт в `<head>` (`base.html.twig`) **до** загрузки CSS: localStorage → `prefers-color-scheme`. Переключатель ☀/☾ — Stimulus-контроллер `theme` (работает и на auth-страницах без React).
- **Едины в обеих темах**: чернильное полотно `--ink-900/800/700` (сайдбар, бренд-панель auth, hero дашборда, primary-кнопки) и письма (email-клиенты сами решают).
- **Тем-независимые пары**: если элемент задаёт и фон, и текст, оба должны переключаться согласованно. `--ink-700` как цвет текста поверх `--ink-100` — запрещено (в тёмной оба тёмные); нейтральный текст на нейтральном фоне — `--chip-neutral-fg`.

## Когда какая кнопка

| Вариант | Применение |
|---|---|
| `btn--brass` | **Одно** главное действие экрана: «+ Новый ученик», «Запланировать», сабмиты рабочих форм |
| `btn--primary` (чернильная) | Сабмиты auth-форм (вход, регистрация) — на «бумаге» без конкуренции с brass |
| `btn--ghost` | Второстепенное рядом с главным: «Отмена», «В архив» |
| `btn--sm` | Действия в строках таблиц и панелях |

Спиннер загрузки — «метроном» (`btn__metronome`), текст кнопки меняется на процессный («Сохраняем…»).

## Музыкальные метафоры: где уместны

- **Да**: заголовки, эйброу («Увертюра», «Реприза»), пустые состояния, названия разделов, роли («дирижёр/первая скрипка/музыкант»).
- **Нет**: подписи полей, ошибки валидации, системные сообщения — там максимально ясный язык («Имя», а не «Солист»).

## Канон пустого состояния

Глиф-нота + тёплая фраза + действие:

```html
<div class="clients__empty">
    <span class="clients__empty-glyph" aria-hidden="true">♪</span>
    В ансамбле пока никого. Добавьте первого ученика.
</div>
```

Примеры фраз — в глоссарии `projectDoc/Симфония-концепция.md`.

## A11y-канон

- Успех/инфо — `role="status"` (вежливый), ошибки — `role="alert"` (ассертивный).
- Поля: `label for` + `aria-invalid` + `aria-describedby` на ошибку (готовый образец — `ui/TextField`).
- Декоративные глифы (♪, иконки категорий) — всегда `aria-hidden="true"`.
- Загрузка контейнеров — `aria-busy`; переключаемые чипы — `aria-pressed`.
- Модалки/палитра: `role="dialog"` + `aria-modal` + **focus trap** (Tab циклится внутри — образец `SearchPalette.trapTab`); закрытие по клику — **только** `e.target === e.currentTarget` (нативные попапы select/date живут вне DOM модалки).
- Live-регионы — только `aria-live="polite"` (не assertive: не перебивать ввод); итог загрузки/поиска анонсировать скрытым `p.visually-hidden` (образец — `admin/UserRoleManager`).
- Кнопки с индикатором — `aria-busy={loading}` (готово в `ui/Button`); текст меняется вместе с состоянием («Сохраняем…»).
- `autoFocus` на загрузке страницы — только когда форма и есть страница (логин); в панелях/формах, открываемых кликом, фокус в первое поле ставить можно (user-initiated).
- Автопроверка: axe-smoke в `assets/tests/react/a11y.test.tsx` (vitest-axe) — новый интерактивный компонент добавлять туда.

## Шрифты

`--font-display` Unbounded — заголовки/бренд; `--font-ui` Golos Text — интерфейс; `--font-mono` JetBrains Mono — данные (email, телефоны, `kbd`).

## Локализация (RU / EN)

Русский — базовый язык, английский — второй. Локаль запроса определяет
`LocaleRequestListener`: параметр пользователя → сессия → `Accept-Language` → `ru`.
Переключатели: гость — кнопка RU/EN на auth-страницах (`POST /locale`, сессия),
залогиненный — секция «Язык интерфейса» в профиле (`PATCH /api/profile`, поле `locale`).

**Правило: новые user-facing строки — только через ключи.** Хардкод русского текста
в разметке — временно допустим лишь на не переведённых пока экранах (CRM-страницы).

- **Twig**: `{{ 'page.login.heading'|trans }}`. Каталоги — `translations/messages.{ru,en}.yaml`.
  Неймспейсы: `layout.*` (shell/auth-layout), `page.*` (страницы), `auth.*` (API-сообщения),
  `frontend.*` (словарь React).
- **PHP**: `TranslatorInterface::trans('auth.…')`. Внутри файрвола (handlers, entry point)
  локаль резолвится явно через `LocaleResolver` — листенер ещё не отработал.
- **Валидаторы**: `message: 'auth.email.blank'` — ключи домена `validators`
  (`translations/validators.{ru,en}.yaml`), переводятся автоматически.
- **React**: `t('frontend.auth.login.submit', 'Войти')` из `assets/react/i18n.ts`.
  Словарь `frontend.*` текущей локали выгружается одним `<script data-i18n>` в
  `base.html.twig` (`frontend_i18n()`). Второй аргумент — русский fallback: он обязан
  побайтово совпадать со значением в `messages.ru.yaml` (fallback держит jsdom-тесты).
- **Даты на фронте**: `toLocaleDateString(uiLocale(), …)` из `assets/react/utils/locale.ts`;
  `'ru-RU'` не хардкодить.
- **Новый язык**: `enabled_locales` в `translation.yaml`, пара каталогов,
  `LocaleResolver::SUPPORTED`, `User::changeLocale()`, `uiLocale()`.

## Чек-лист нового компонента

1. Цвета — только `var(--…)`; прозрачности — `*-rgb`.
2. Пары фон/текст тем-независимы (проверить в обеих темах на `/styleguide`).
3. Пустое состояние по канону; загрузка с `aria-busy`.
4. Строки — через ключи каталога (раздел «Локализация» выше): Twig — `|trans`, React — `t()`.
5. Добавить пример на витрину `/styleguide`.
6. Интерактивный компонент — axe-smoke в `a11y.test.tsx`; live-регионы/фокус — по A11y-канону выше.
