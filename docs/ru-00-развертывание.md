# 0. Разворачивание проекта

## Требования

| Инструмент | Версия |
|-----------|--------|
| Docker Desktop | Последняя |
| Docker Compose | Встроен в Docker Desktop |
| Node.js + npm | Для локальной сборки ресурсов (не обязательно — можно внутри контейнера) |
| Git | Для клонирования репозитория |

## Первый запуск (разработка)

### 1. Клонировать репозиторий

```bash
git clone <url-репозитория>
cd petSymphony
```

### 2. Настроить переменные окружения

Создайте файл `.env.local` для локальных переопределений (не коммитится в git):

```bash
# .env.local — только то, что отличается от .env
POSTGRES_PASSWORD=мой_пароль
```

> **Важно:** Никогда не меняйте пароли напрямую в `.env` — этот файл коммитится.
> Используйте `.env.local` или `.env.dev.local`.

### 3. Собрать и запустить Docker-контейнеры

```bash
# Собрать образы (первый раз или после изменений Dockerfile)
docker compose build --pull --no-cache

# Запустить все сервисы и дождаться готовности
docker compose up --wait
```

После `--wait` команда вернётся только тогда, когда все контейнеры (`php`, `database`, `node`) пройдут healthcheck.

### 4. Собрать frontend-ресурсы

Контейнер `node` запускается автоматически и следит за изменениями в `assets/`. При первом запуске он устанавливает зависимости и собирает ресурсы. Следить за процессом:

```bash
docker compose logs -f node
```

Если нужна разовая сборка вручную:

```bash
docker compose run --rm node npm run dev
```

### 5. Открыть приложение

| URL | Описание |
|-----|---------|
| `https://localhost/` | HTTPS (основной) |
| `http://localhost/` | HTTP |

> При первом запуске браузер покажет предупреждение о самоподписанном сертификате — это нормально для dev-окружения. Нажмите «Дополнительно → Всё равно перейти».

## Структура Docker Compose

### `docker-compose.yaml` (базовый)

Определяет два сервиса: `php` (FrankenPHP) и `database` (PostgreSQL).

### `compose.override.yaml` (автоматически подключается в dev)

- Монтирует текущую директорию в `/app` внутри контейнера (hot-reload кода без пересборки)
- Включает режим наблюдения FrankenPHP: `FRANKENPHP_WORKER_CONFIG=watch`
- Пробрасывает порт БД `5432:5432` на хост (для подключения из IDE/клиента)
- Устанавливает `XDEBUG_MODE` из переменной среды хоста
- Добавляет сервис `node` — контейнер с Node.js 22, который следит за изменениями в `assets/` и пересобирает frontend-ресурсы

### `compose.prod.yaml` (для продакшена)

Используется только при явном указании флага `-f compose.prod.yaml`.

## Полезные команды Docker

```bash
# Остановить и удалить контейнеры
docker compose down --remove-orphans

# Перезапустить без пересборки
docker compose up --wait

# Посмотреть логи в реальном времени
docker compose logs --tail=0 --follow

# Войти в shell контейнера php
docker compose exec php sh
# или bash (с историей команд)
docker compose exec php bash

# Выполнить команду в контейнере
docker compose exec php bin/console about
```

## Работа с базой данных

### Выполнить миграции

```bash
docker compose exec php bin/console doctrine:migrations:migrate
```

> Миграции также запускаются автоматически при старте контейнера через `docker-entrypoint.sh`.

### Создать новую сущность (Entity)

```bash
docker compose exec php bin/console make:entity
```

### Сгенерировать миграцию после изменения сущностей

```bash
docker compose exec php bin/console make:migration
```

### Подключение к БД из клиента (DBeaver, DataGrip и т.д.)

| Параметр | Значение |
|---------|---------|
| Host | `localhost` |
| Port | `5432` |
| Database | `app` |
| User | `app` |
| Password | `!ChangeMe!` (или ваше из .env.local) |

## Сборка frontend-ресурсов (Webpack Encore)

| Команда | Описание |
|--------|---------|
| `npm run dev` | Собрать один раз (для разработки) |
| `npm run watch` | Следить за изменениями и пересобирать автоматически |
| `npm run dev-server` | Dev-сервер с горячей перезагрузкой (HMR, порт 8080) |
| `npm run build` | Оптимизированная сборка для продакшена |

Все собранные файлы попадают в `public/build/`.

## Развёртывание в продакшене

```bash
# Собрать продакшен-образ
docker compose -f compose.yaml -f compose.prod.yaml build --pull --no-cache

# Запустить с секретными переменными
SERVER_NAME=your-domain.com \
APP_SECRET=ВашСекретныйКлюч \
CADDY_MERCURE_JWT_SECRET=ВашМеркурКлюч \
docker compose -f compose.yaml -f compose.prod.yaml up --wait
```

> **Порядок флагов `-f` важен.** `compose.prod.yaml` должен идти вторым.

Подробнее — в файле `docs/ru-production.md`.

## Часто встречаемые проблемы

### Порты заняты

Если порт 80 или 443 уже занят другим процессом — остановите его или измените порты в `compose.override.yaml`.

### Права доступа на Linux

```bash
docker compose run --rm php chown -R $(id -u):$(id -g) .
```

### Кэш нужно сбросить

```bash
docker compose exec php bin/console cache:clear
```
