# QA — ручное тестирование подключённых проектов

Индекс-нота (MOC) для ручного прогона тест-кейсов внешних проектов, подключённых
к **petSymphony** как git-submodules и видимых в меню **«Оркестр → Проекты»**
(`/projects`).

Каждый проект тестируется по двум осям:

- **Доступ через Оркестр** — карточка на `/projects`, переход на поддомен,
  диагностика при недоступности (smoke интеграции).
- **Функциональность приложения** — основные пользовательские сценарии плюс
  негативные/граничные случаи.

## Общие предусловия (для всех прогонов)

1. **Поднять основной стек** petSymphony из корня проекта:
   ```bash
   docker compose up --wait
   ```
2. **Поднять подключённые проекты** через оркестратор:
   ```bash
   sh bin/projects up
   ```
3. После старта/изменения списка проектов — **перечитать конфигурацию Caddy**,
   чтобы поддомены `*.localhost` начали проксироваться:
   ```bash
   docker compose restart php
   ```
4. **Сертификаты**: поддомены отдаются по HTTPS с самоподписанным сертификатом
   FrankenPHP/Caddy. В браузере один раз подтвердить доверие (или добавить
   корневой сертификат в доверенные) для `*.localhost`.
5. **Per-app окружение и порты** заданы в `.env`-файлах самих сабмодулей
   (см. таблицу предусловий в каждом проектном доке). Маппинг карточек,
   поддоменов и стека — в `config/projects.yaml`.
6. **Креды** для входа — демо-пользователи из таблицы выше (сидируются миграциями
   сабмодулей).

> [!info] Диагностика доступа
> Если поддомен отдаёт **502** или не открывается — порядок диагностики
> (статус контейнеров, перезапуск `php`, проверка проксирования) описан в
> `docs/ru-проекты.md`. Карточки и маршрутизация — `config/projects.yaml`.

## Легенда приоритетов

| Приоритет | Когда присваиваем |
| --- | --- |
| **Высокий** | Ключевой happy-path или интеграция; блокирует приёмку при провале |
| **Средний** | Важная, но не блокирующая функция; обходной путь существует |
| **Низкий** | Граничный/косметический случай, редкий сценарий |

## Шаблон тест-кейса

Каждый кейс в проектных доках оформлен единообразно:

- **ID** — сквозной идентификатор (`YMP-…`, `FN-…`); префикс `A` — кейсы доступа
  через Оркестр.
- **Заголовок** — кратко суть проверки.
- **Приоритет** — Высокий / Средний / Низкий (см. легенду).
- **Предусловия** — что должно быть выполнено до шагов (помимо общих выше).
- **Шаги** — нумерованные действия тестировщика.
- **Ожидаемый результат** — наблюдаемое поведение, по которому кейс
  засчитывается как пройденный.

> [!note] Как прогонять
> Открыть нужный проектный док в Obsidian, выполнить общие предусловия выше,
> затем идти по кейсам сверху вниз: сначала раздел **A** (доступ), потом **B**
> (функциональность), потом **C** (негатив/границы). Результат фиксировать рядом
> с ID (например, ✅/❌ + заметка).
