# Тест-кейсы — Яндекс.Карты: парсер отзывов

← Назад к индексу: [[README]]

## Описание

`yandex-maps-parser` — внешний проект, подключённый к petSymphony как
git-submodule и доступный через **«Оркестр → Проекты»**. Это SPA на **Vue 3**
поверх API на **Laravel 13** (аутентификация — Sanctum, cookie-сессия) и
отдельного скрапера на **Node/Playwright**. Базовый сценарий: вход → вставка
ссылки на организацию в Яндекс.Картах → асинхронный парсинг → опрос статуса →
отображение среднего рейтинга, счётчиков и списка отзывов с пагинацией.

## Предусловия / окружение

> Сначала выполнить **общие предусловия** из [[README]] (поднять стек,
> `sh bin/projects up`, `docker compose restart php`, доверие сертификату).

| Параметр | Значение |
| --- | --- |
| URL приложения | `https://yandex-maps-parser.localhost` |
| Порт сабмодуля | `APP_PORT=8082` |
| Демо-пользователь | `admin@example.com` / `password` |
| API-эндпоинты | `/api/login`, `/api/organization`, `/api/organization/status`, `/api/organization/reviews`, `/api/organization/refresh` |
| Скрапер | Node/Playwright (асинхронный, статусы парсинга) |

> [!warning] Сверка значений
> Эндпоинты, статусы и коды ошибок ниже сверять с исходниками сабмодуля при
> локальном прогоне: `projects/yandex-maps-parser/backend/routes/api.php` и
> README сабмодуля (поток статусов, `captcha`/`markup_changed`).

## A. Доступ через Оркестр

### YMP-A01 · Карточка проекта на `/projects`
- **Приоритет:** Высокий
- **Предусловия:** стек и проекты подняты.
- **Шаги:**
  1. Открыть `https://localhost/projects` (меню «Оркестр → Проекты»).
  2. Найти карточку парсера Яндекс.Карт.
- **Ожидаемый результат:** карточка отображает название, описание, стек
  «Laravel 13 · Vue 3», иконку 🗺️ и ссылку на приложение; данные совпадают с
  `config/projects.yaml`.

### YMP-A02 · Переход по карточке открывает приложение
- **Приоритет:** Высокий
- **Предусловия:** YMP-A01 пройден.
- **Шаги:**
  1. На `/projects` кликнуть по карточке (или её ссылке).
- **Ожидаемый результат:** открывается `https://yandex-maps-parser.localhost`,
  загружается Vue-SPA, показан экран логина (пользователь не авторизован).

### YMP-A03 · (нег.) Приложение не поднято → диагностика
- **Приоритет:** Средний
- **Предусловия:** контейнер парсера остановлен (`sh bin/projects` не поднимал
  его или он упал).
- **Шаги:**
  1. Перейти на `https://yandex-maps-parser.localhost`.
- **Ожидаемый результат:** Caddy отдаёт **502** (или иную явную ошибку прокси);
  порядок диагностики соответствует `docs/ru-проекты.md` (проверка статуса
  контейнеров, `docker compose restart php`).

## B. Функциональность приложения

### YMP-01 · Успешный вход
- **Приоритет:** Высокий
- **Предусловия:** открыт экран логина; пользователь `admin@example.com` сидирован.
- **Шаги:**
  1. Ввести `admin@example.com` / `password`.
  2. Нажать «Войти».
- **Ожидаемый результат:** вход успешен, открывается экран настроек/ввода ссылки;
  установлена cookie-сессия Sanctum.

### YMP-02 · Неуспешный вход (неверный пароль)
- **Приоритет:** Высокий
- **Предусловия:** экран логина.
- **Шаги:**
  1. Ввести `admin@example.com` и заведомо неверный пароль.
  2. Нажать «Войти».
- **Ожидаемый результат:** показано сообщение об ошибке авторизации; вход не
  выполнен; на защищённые экраны не пускает.

### YMP-03 · Валидация формы логина
- **Приоритет:** Средний
- **Предусловия:** экран логина.
- **Шаги:**
  1. Отправить форму с пустыми полями.
  2. Ввести некорректный email (например, `admin@`) и отправить.
- **Ожидаемый результат:** для пустых полей и некорректного email выводятся
  ошибки валидации; запрос на сервер с невалидными данными не уходит/отклоняется.

### YMP-04 · Доступ к защищённым экранам без авторизации
- **Приоритет:** Высокий
- **Предусловия:** пользователь не авторизован (нет сессии).
- **Шаги:**
  1. Попробовать открыть защищённый экран напрямую (URL экрана парсинга).
  2. Либо вызвать защищённый API без cookie.
- **Ожидаемый результат:** SPA редиректит на логин; защищённый API отвечает
  `401 Unauthorized`.

### YMP-05 · Выход (logout)
- **Приоритет:** Средний
- **Предусловия:** пользователь авторизован.
- **Шаги:**
  1. Нажать «Выйти».
- **Ожидаемый результат:** сессия завершена, показан экран логина; повторный
  доступ к защищённым экранам требует входа.

### YMP-06 · Сохранение сессии после перезагрузки
- **Приоритет:** Средний
- **Предусловия:** пользователь авторизован (YMP-01).
- **Шаги:**
  1. Перезагрузить страницу (F5).
- **Ожидаемый результат:** пользователь остаётся авторизованным (cookie-сессия
  Sanctum сохраняется), повторный логин не требуется.

### YMP-07 · Запуск парсинга по валидной ссылке
- **Приоритет:** Высокий
- **Предусловия:** пользователь авторизован.
- **Шаги:**
  1. Вставить валидную ссылку на организацию в Яндекс.Картах.
  2. Запустить парсинг.
- **Ожидаемый результат:** задача создаётся, статус переходит в `processing`
  (UI показывает индикатор/ожидание).

### YMP-08 · Опрос статуса до завершения
- **Приоритет:** Высокий
- **Предусловия:** запущен парсинг (YMP-07).
- **Шаги:**
  1. Дождаться периодического опроса статуса (≈3 c, эндпоинт
     `/api/organization/status`).
- **Ожидаемый результат:** статус становится `done`; в UI появляются средний
  рейтинг и счётчики; индикатор ожидания исчезает.

### YMP-09 · Просмотр отзывов с пагинацией
- **Приоритет:** Высокий
- **Предусловия:** парсинг завершён (`done`), отзывы есть.
- **Шаги:**
  1. Открыть список отзывов.
  2. Переключить страницы вперёд/назад.
- **Ожидаемый результат:** отзывы выводятся постранично (≈50 на страницу),
  переключение страниц подгружает соответствующую порцию без потери контекста.

### YMP-10 · Средний рейтинг и счётчики
- **Приоритет:** Средний
- **Предусловия:** парсинг завершён.
- **Шаги:**
  1. Сверить отображаемый средний рейтинг и счётчики (число отзывов и т.п.) с
     карточкой организации в Яндекс.Картах.
- **Ожидаемый результат:** значения корректны и соответствуют источнику.

### YMP-11 · Повторный парсинг кнопкой «Обновить»
- **Приоритет:** Средний
- **Предусловия:** есть ранее распарсенная организация.
- **Шаги:**
  1. Нажать «Обновить» (refresh, `/api/organization/refresh`).
  2. Дождаться завершения.
- **Ожидаемый результат:** запускается повторный парсинг; по завершении данные
  (рейтинг/счётчики/отзывы) обновляются актуальными значениями.

### YMP-12 · Кэш: повторное открытие без скрейпинга
- **Приоритет:** Низкий
- **Предусловия:** организация уже распарсена и сохранена.
- **Шаги:**
  1. Открыть ту же организацию повторно (без «Обновить»).
- **Ожидаемый результат:** данные отдаются из БД мгновенно, без повторного
  запуска скрапера.

## C. Негативные и граничные случаи

### YMP-13 · Невалидный URL организации
- **Приоритет:** Высокий
- **Предусловия:** пользователь авторизован.
- **Шаги:**
  1. Вставить не-Яндекс ссылку или мусорную строку.
  2. Запустить парсинг.
- **Ожидаемый результат:** показана ошибка валидации; парсинг не запускается.

### YMP-14 · Капча при парсинге
- **Приоритет:** Средний
- **Предусловия:** парсинг приводит к капче на стороне Яндекса.
- **Шаги:**
  1. Запустить парсинг для кейса, где скрапер ловит капчу.
- **Ожидаемый результат:** статус/ошибка `captcha` корректно отражается в UI
  понятным сообщением; приложение не «зависает».

### YMP-15 · Изменение вёрстки источника
- **Приоритет:** Низкий
- **Предусловия:** скрапер не может распарсить ожидаемую структуру.
- **Шаги:**
  1. Запустить парсинг для кейса с изменившейся/неожиданной вёрсткой.
- **Ожидаемый результат:** возвращается ошибка `markup_changed`; UI показывает
  понятное сообщение, статус не остаётся вечно в `processing`.

### YMP-16 · Таймаут/недоступность скрапера
- **Приоритет:** Средний
- **Предусловия:** сервис скрапера остановлен или не отвечает.
- **Шаги:**
  1. Запустить парсинг.
  2. Дождаться истечения таймаута.
- **Ожидаемый результат:** статус переходит в `failed`; пользователю показано
  понятное сообщение об ошибке; возможен повтор.

### YMP-17 · Организация без отзывов
- **Приоритет:** Низкий
- **Предусловия:** пользователь авторизован.
- **Шаги:**
  1. Распарсить организацию, у которой нет отзывов.
- **Ожидаемый результат:** парсинг завершается `done`; список отзывов пуст
  (корректное пустое состояние), счётчики показывают 0 без ошибок.
